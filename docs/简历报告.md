## 第一部分：Text-to-SQL 智能数据分析助手（项目经历）

**技术栈**：Python / LangChain v1 / DeepSeek / Spring Boot 3 / Vue3 / MySQL 8 / Chroma —— 主导设计与 AI 协作开发，已上线 https://sql.shanghl.club

**项目简介**：面向非技术用户的中文自然语言数据分析系统：单 Agent 通过混合检索获取表结构与业务口径，生成只读 SQL 查询 37 万行电商数据集，支持流式回答、人工审批与用户自带 Key（BYOK）。自建评测集与消融体系完成全链路量化验证。

- **架构设计**：设计"Java 工程化 + Python 大脑"双服务架构——Spring Boot 网关承担鉴权/限流/审计/密钥管理，LangChain Agent 承担检索/推理/SQL 生成；确立"读路径给模型、写路径与安全边界不给模型"的职责边界（查询历史落库走网关后处理而非模型工具，避免审计依赖被审计者）
- **RAG 检索层**：设计三路语料（表结构/业务口径/用户反馈自举的 few-shot 示例）+ BM25/向量双路混合检索（自实现 RRF 融合）；建立语料质量门（六道门槛 + 文本归一/语义 0.92 双层去重），点赞样本经人工审核后进入语料库形成自进化闭环
- **四层 SQL 安全防线**：DB 只读账号 → 会话级只读 → sqlglot AST 语义白名单（根节点类型/锁读/INTO/危险函数四类规则，替换正则消除字面量误杀与子查询漏判）→ 服务端执行超时；另支持 LangGraph 原生中断的 SQL 执行前人工审批（HITL），多语句场景遵循"未过目 SQL 一律拒绝"安全不变量
- **BYOK 密钥管理**：设计用户自带 LLM Key 的全链路方案——AES-256-GCM 加密落库（IV 每次随机）、免费幂等的 /models 校验、指纹脱敏（日志 grep "sk-" 恒为 0）、内网头传递、服务端结构性不留站点级 Key
- **评测与消融**（量化能力核心证据）：自建 50 条评测集（五类题型 + 示例/近例/远例三层分层），设计 9 组单变量消融（OAT 策略，1274 次运行，语料冻结 + 预注册纪律）：**RAG 整体 +12.7pp**（SQL 级 14.0%→26.7%，~2.5σ）、**few-shot 路为最大单项**（去掉 −16.7pp，示例层 52%→9% 崩塌）、**bge-reranker 重排为负结果**（−4.0pp）但归因到机制（schema 召回 +31pp 换 glossary −8.4pp 的类型挤出）；全部数字经 1274 条记录真库重放独立复算零翻转
- **线上工程**：2C2G 单机原生部署（systemd 双服务内存封顶 + nginx 共存站点 + 证书自动续期）；排障实录含 JDK HttpClient h2c 升级头被 uvicorn 拒绝、fastembed 模型缓存离线化、Pinia 响应性丢失导致的流式不渲染等，均有根因链与回归测试

**测试账本**：pytest 423 + JUnit 47 + vitest 42 ≈ 512 项；六轮独立代码审查（含 BYOK 密钥泄漏面穷举、对抗 SQL 40 组、限流绕过实测复现），审查发现的 P1 均已在生产验证修复。

## 第二部分：AI 协作的开发方法论（怎样用 AI 做工程）

**定位**：在 19 天内完成上述全栈 AI 应用的设计-开发-上线-量化闭环。我的角色不是"让 AI 写代码的人"，而是**系统设计者与质量负责人**——AI 承担实现执行，我承担架构决策、验收标准与质量门设计。

- **多 Agent 协作体系设计**：将开发流程组织为"主 Agent（协调）+ 设计/编码/调研/审查四类专职子 Agent"的分工结构；每周里程碑固定执行"设计先行 → 我拍板开放问题 → 双工单并行编码 → 独立审查 → 修复验证 → 教学沉淀"六步闭环，19 天完成原计划 8 周的工程量且每步可追溯（git 60+ commits）
- **用决策框架驾驭 AI 而非被 AI 带着走**：所有关键选型（向量库 Milvus→Chroma 的资源约束回退、BYOK 落库 vs 透传、HITL 暂停点在工具层 vs 网关层、OAT vs 全因子消融）都由我基于 AI 给出的 A/B 论证做最终拍板——AI 产出选项与理由，**决策权与责任边界始终在我**
- **给 AI 立工程纪律**（设计能力的核心体现）：
  - **预注册预期**——消融每行跑之前写下预期方向，跑出"意外正向"才能称为发现而非调参
  - **语料冻结 + 语料指纹**——每行实验记录 git commit 与片数，汇总前断言一致，杜绝自举功能污染正在进行的实验
  - **同构闸门**——重构前后固定题的检索注入序列必须逐元素全等，保证评测数字跨版本可比
  - **审查独立于编码**——审查 Agent 只读且必须独立复算数字（1274 条真库重放）、实测攻击（限流绕过、40 组对抗 SQL），不是走过场
- **人机边界的清醒划分**：我做需求定义、关键决策、上线验收、实验观察与 bug 报告（如流式不渲染的复现条件）；AI 做方案枚举、编码、测试、文档；**AI 的每个"设计假设必须实测"原则两次抓出重大隐患**（HITL resume 载荷格式、断连 GeneratorExit 不投递）
- **量化与诚实文化**：消融跑出 rerank 负结果不掩盖，归因到 Recall 拆解；+4.6pp 的边际效应因未超运行方差（~1σ）主动降格措辞为"方向性观察"——这套数字纪律在独立审查中获得"1274 条记录复算零翻转"的背书

**一句话总结**：AI 把"一个人写不完的代码量"变成了"一个人设计得过来的系统"——前提是你为它设计好决策框架、质量门和诚实约束。
