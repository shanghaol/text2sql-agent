## 二、五个发现（每个都是面试弹药）

### 发现 1：few-shot 是最大单项贡献者（−16.7pp）

去掉 few-shot 路比**完全无 RAG** 还惨（10.0% vs 14.0%）——schema/glossary 片仍注入但救不了。分层实锤：hit 层 52%→9%（崩塌）、far 层 25%→12%（也掉了！）。**far 层也掉**说明 few-shot 的作用不止"提供可套模板"——示例还隐式示范了 SQL 风格、时间写法、口径处理，这些对没见过同款题的 far 层同样有效。

**面试一句话**：RAG 系统里最值钱的往往不是知识库本体，而是高质量示例——我的消融把这一点量化到了 16.7 个点。

### 发现 2：RRF k=10 是意外正向收益（+4.6pp）

设计预注册时预期"变化小"（k 平滑排名差距，小语料头部稳定）。实际 k=60 的过度平滑让头部优势稀释——k=10 排名更陡峭，示例片更稳进 top-8（hit 层 52%→64%）。**预注册的意义**：如果没提前写下预期，这个发现就说不清是"调出来的"还是"真效应"；预注册后它是有对照的正向优化。

### 发现 3：rerank 是诚实负结果（−4.0pp）

Recall 拆解揭示机制：**schema 召回 +31pp（52.7%→83.9%，rerank 干了它的活）但 glossary 被挤出（91.7%→83.3%）**——rerank 按 query-文档相似度排位，口径片与问题的字面相似度天然低（用户问"GMV 多少"，口径片讲的是"GMV 的定义与计算方式"，词汇重叠少），在 top-8 预算内被 schema 片挤掉→口径题答错。修法明确（W7：按 doc_type 配额保留），但当前形态净负。

**面试一句话**：负结果的归因比正向结果的宣布更难也更值钱——"我测过、我知道为什么负、我知道怎么修"三层认知，只有真做过消融的人才答得出来。

### 发现 4：BM25 边际贡献仅 −2.0pp

W2 时代"表名列名靠 BM25 保命"的预期在 50 题上只兑现 2 个点。机制推测：向量路（bge-small-zh）对常见中文字面量的覆盖已够，BM25 的独特价值区（精确 token）在这套题里占比小。**但这不等于 BM25 该删**：−2.0pp 是真实贡献，且 C 行（纯 BM25）答案级反而 +5.4pp 的现象提示两路在不同指标上有微妙互补。

### 发现 5：top_n 不敏感（D1/D2 都在 ±2pp 内）

5 片与 12 片几乎无差——**注入预算不是瓶颈，瓶颈在片的相关性质量**（F 行的 glossary 被挤掉正是质量问题的体现）。这个"什么不重要"的结论直接指导 W7 优化方向：别调注入数量，去修 rerank 的类型挤出问题。

## 三、面试考点（四件套）

### 3.1 "你的消融实验怎么设计的？"（方法论总题）

**考察意图**：区分"跑过几组数字"和"懂实验设计"。OAT vs 全因子的选择是分水岭。

**参考答法（90 秒口语稿）**：
> 单变量逐项消融（OAT）：9 行实验，每行只改一个变量（去 BM25/去向量/top_n/k/rerank/去 few-shot/无 RAG），其余全部锁定线上默认值，每行 3 runs 控方差。**没做全因子**（3×2×2×2=48 格）：一是预算（1100 次已 ≈10M token），二是交互项在 ±5-10pp 的 run 间方差下根本测不出显著——OAT 的归因清晰度远超其理论损失。
> 两条纪律保数字可信：① **语料冻结**——消融窗口内语料文件不动，每行 detail 记 git commit + 片数，汇总前断言全部一致（W5 自举上线后语料漂移是真实风险）；② **预注册预期**——每行跑之前写下预期方向，E 行（k=10）的意外正向因此才能叫"发现"而不是"调参调出来的"。

**可能的追问**：
- "为什么不跑更多 runs？"→ 3 runs 下 Δ<方差的行诚实写"不敏感"（top_n 行即是）；runs 数是成本与置信度的平衡，报告附各 run 值供自行判断。
- "负结果为什么不修了再报？"→ 修法明确（doc_type 配额）但那是 W7 的实验；W6 报的是当前形态的诚实数字——先有可信基线才有可信优化。

### 3.2 "RAG 到底带来了多少提升？怎么证明的？"（核心因果题）

**参考答法**：
> 两个口径都测了：**整体育退**（top_n=0，走线上真实降级链路而非删代码）——SQL 级 14.0% vs 26.7%（+12.7pp）；**组件级拆解**——few-shot 路单独 −16.7pp（比整体还大，因为去掉后 schema/glossary 还在但反而更差：10.0% vs 无 RAG 的 14.0%，说明低质量注入比没有注入更干扰）。分层看更细：示例层去掉 few-shot 从 52% 崩到 9%，远例层也掉 13 个点——示例的价值不止模板还有风格隐式教学。
> 答案级（含 Agent 文本计算兜底）RAG 只差 3.3pp——这本身是发现：模型"知道查哪张表"之后，算对大部分题靠的是文本计算而非单条 SQL。

### 3.3 "rerank 为什么是负的？讲讲机制"（负结果深挖题，答好极加分）

**参考答法**：
> 表面数字 −4.0pp，但拆 Recall 才看到机制：rerank 把 schema 召回从 52.7% 提到 83.9%（+31pp，它确实干了它的活），**代价是把 glossary 从 91.7% 挤到 83.3%**。机制：bge-reranker 按 query-文档语义相似度排位，而口径片与问题的字面相似度天然低——用户问"GMV 多少"，口径片讲"GMV 的定义"，词汇重叠少；schema 片（表名列名）与问题重叠高。top-8 预算内零和挤压，口径片出局→口径题答错。
> 修法明确：rerank 后按 doc_type 配额保留（每类至少 N 片）——W7 验证。但 W6 的结论就是负的，我不修数字。

### 3.4 "判定器改了，旧数字还有效吗？"（工程严谨题）

**参考答法**：
> 判定器 v2.1 修的是无序比较的排序键（字符串序→数值序），修前用**离线 rejudge** 复判了 W3 的全部 132 次运行——detail JSON 存了每次的 SQL 和最终回答，判定是确定性函数，不需要重跑 LLM。结果：**零翻转**，41.1%/64.4% 稳健。唯一 1 次 pass_via 变化被自动归因为 W5 超时防线改变了重放环境（4 子查询金标现在触发 3024 超时，三级规则回退首条）——成因归类机制防住了"环境差异被误读为判定器效应"。
> 方法论：**判定逻辑变更必须复判历史数据**，且要区分"判定器效应"与"环境效应"。

## 四、动手实验（五要素）

### 4.1 实验一：复算消融数字（数字考古）

- **验证目标**：亲手验证简历数字的可复现性
- **操作**：读 `eval/reports/detail_baseline_50_*.json` 与 `detail_no_fewshot_*.json`，独立数 pass 计数÷总数，对照报告尾部
- **预期现象**：26.7%（40/150）与 10.0%（15/150）精确复现
- **思考题**：为什么答案级的分母也是 150 而不是"SQL 级 fail 的那些"？（双层指标定义：答案级=SQL 判过+文本判过的超集，分母恒为全部运行）

### 4.2 实验二：亲手触发 rerank 的类型挤出（机制复现）

- **验证目标**：亲眼看 glossary 被挤出 top-8
- **操作**：`.venv/Scripts/python -c "..."` 构造 retriever（rerank_pool=16 + 真 reranker），对"上个月的退款率是多少"分别跑无 rerank 与有 rerank，打印两次的注入片 id 列表
- **预期现象**：rerank 后 schema 片上位、`glossary:refund_rate` 掉出 top-8（或排位大跌）
- **思考题**：如果按 doc_type 配额（schema 最多 4 片），挤出问题解决但牺牲什么？（schema 召回的绝对量——配额是新的零和，需要实验找平衡）

### 4.3 实验三：预注册一行的复跑（方差体验）

- **验证目标**：体验 run 间方差，理解"Δ<方差不结论"
- **操作**：`python -m eval.run_eval --tag e_row_verify --rrf-k 10 --runs 1`（E 行再跑一次单 run）
- **预期现象**：单 run 的 SQL 级在 24%-36% 区间波动（3 runs 是 31.3%）——肉眼看到方差幅度，理解为什么 D1/D2 的 ±2pp 不下结论
- **思考题**：要测出 +2pp 的显著效应需要多少 runs？（粗估：方差 σ≈5pp 时，n≈(2σ/Δ)²≈25 组——这就是"不敏感"结论的统计学根基）

### 4.4 实验四：离线 rejudge 的机制理解

- **操作**：读 `eval/rejudge.py`（150 行），理解它如何从 detail JSON 复原判定输入
- **思考题**：为什么 rejudge 不需要 API key？（判定是确定性函数——SQL 重放连的是本地 MySQL，文本回退是纯函数；唯一的环境依赖是数据库状态，所以 W5 超时防线才会造成那 1 次环境效应）

## 五、审查战果（2026-10-12，独立审查子 Agent）

**总结论：数字可信可提交。** 审查方式：**不信任存储字段，从 detail JSON 逐条独立重算 + MySQL 真库全量重放重推导**（1274 条零 LLM 成本）——每个汇总数字都复现，判定零翻转。

**实证清单**：
- 语料冻结：10 份 detail 全部 corpus_commit=3b98c3a / 28 片，git diff 对语料/数据集/agent 均空
- 参数真实生效：B 行 enable_bm25=false、G 行 0 次 qa_pair 注入、F 行 150/150 注入集合与基线**均不同**（重排真实发生非摆设开关）
- 同构性：H 行与 W3 基线共享的 90 个 (id, run) 键注入序列逐元素全等

**P1 教训（最有价值的一条）**：E 行"+4.6pp"逐 run 波动 32/24/38%，差异约 1σ 未超运行方差——审查要求简历措辞从"优化 +4.6pp"降格为"方向性观察"。**这是统计学对简历工程的纠偏**：主数字（RAG +12.7pp ~2.5σ、few-shot −16.7pp >3σ）显著成立，但边际效应必须带方差口径——面试官若追问"这个提升显著吗"，只有提前想清楚 σ 的人答得上来。顺带修正实际运行次数 1100→1274（低报非虚增，诚实记账）。
